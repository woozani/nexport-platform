## 2. 제품 방향 핵심 결정사항

### 2-1. 포지셔닝: DB 제공 < 컨택 중심
- DB 제공은 "데이터를 조금 더 편하게 보여주는" 보조 기능으로 격하
- 핵심 가치 = **적합 기업 추출 → 전환율 높은 맞춤형 메일 대량 발송 → 회신만 먹기 좋게 정리**
- 양질의 자체 DB가 쌓이기 전까지는 DB 브라우징/시각화를 전면에 내세우지 않음

### 2-2. 확정된 핵심 유저 플로우 (외주사 제안, Jay 동의)
1. 유저가 필터링 조건 설정
2. 메일링 발송 대상 리스트업 (자동)
3. 유저가 제외할 대상 제거
4. AI 메일 생성 시작 → "AI가 돌아가고 있습니다" 로딩 → 완료된 건부터 순차 표시
5. 메일 전문 클릭해서 확인 + 직접 수정 가능
6. 발송 전 확인 팝업 2~3회 ("진짜 발송합니다. 확실하신가요?") — **책임 소재를 유저에게** (AI 작성물 사전 승인 구조)
7. 발송
8. 회신 수집 → 회신 내용 전반 평가/관리

### 2-3. 걷어낼 것 (당장 불필요)
- 화려한 DB 시각화 (양질 DB 확보 전)
- 커뮤니티/체류시간 늘리기 기능 ("초반에 그런 거 다 필요 없어")
- 기업 상세 정보 장문 표시 → 3문단짜리는 **완전 요약**해서만 표시

### 2-4. 유저 온보딩 필수 요소
- AI가 맞춤형 메일을 쓰려면 **고객사 제품에 대한 이해가 필요** → 가입/온보딩 시 제품·회사 설문 입력 구조 필요
- 바이어 기업별 컨택 포인트: AI가 회사별로 조사하게 하거나, 초기에 수기 작성

### 2-5. 차별화 아이디어 (중장기)
- **회신 데이터 기반 가치 창출**: 회신 내용에서 제품 피드백·메일 보강점 도출
- **내부 데이터 기반 칼럼**: "바이어 성사율을 높이려면" 류 — 외부 뉴스 크롤링은 가치 낮음 ("유베스팅 닷컴에서 다 보니까")
- **뉴스레터 마케팅**: 무료 체험자에게 뉴스레터 구독 유도 → 전문 클릭 시 서비스 유입 (CAC 절감)

### 2-6. Apollo.io 반면교사 (Jay 실사용 소감)
