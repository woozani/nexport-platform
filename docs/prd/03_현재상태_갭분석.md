# 현재 NEXPORT 프로토타입 vs PRD 목표 — 갭 분석
**목적:** "현재 넥스포트는 PRD 작성에 적합하지 않다"의 구체화. 무엇을 유지/축소/제거/신규해야 PRD 기준 제품이 되는지 정의.

> 현재 프로토타입(src/App.jsx, ~5,500줄, 전부 Mock)은 **"보여주기용 데모"**로 설계됨.
> PRD 목표 제품은 **"컨택 단일 플로우"**. 방향이 다르므로 기능 단위로 재분류한다.

---

## 1. 기능별 처리 방침

| 현재 기능 (App.jsx) | 미팅 결정 기준 | 방침 |
|---|---|---|
| 랜딩 페이지 (Hero, ROI 위젯, VOC 인용) | 마케팅 자산 | ✅ **유지** (제품과 분리된 마케팅 페이지) |
| 바이어 탐색 (지도 시각화, 카드 리스트) | "DB 시각화 걷어내라" | 🔻 **축소** → 필터링+리스트업 화면으로 전환 |
| 바이어 상세 (장문 기업 정보) | "3문단 → 완전 요약" | 🔻 **축소** → 1줄 요약 + 확장 행 |
| AI 매칭 (매칭 스코어 시각화) | 알고리즘 근거 미확정, 접근 B 채택 | ⛔ **전면 보류** (사전 스코어링 대신 발송→회신 필터) |
| 이메일 발굴 (Hunter.io) | 데이터 파이프라인으로 흡수 | 🔻 **백엔드화** (유저 노출 화면 아님) |
| 대시보드 | P1 유지 | ✅ 유지 (지표를 발송/회신 중심으로 재정의) |
| 무역 뉴스 (TradeNewsView) | "외부 크롤링은 큰 게 없다" | ⛔ **보류** (내부 데이터 칼럼으로 대체, P2) |
| 신용 리포트 (CreditReportView) | 미팅 논의 없음, 코어 아님 | ⏸ **보류** (P2 후보) |
| 시장 동향 (MarketView) | "유베스팅 닷컴에서 다 본다" | ⛔ **보류** |
| 플레이북 | 코어 아님 | ⏸ 보류 |
| 카카오 채널 버튼 | CS 채널 | ✅ 유지 |

## 2. 신규 필요 (현재 없음 — PRD의 본체)

| 신규 기능 | 근거 |
|---|---|
| 온보딩: 제품 프로필 설문 | AI 메일의 원천 데이터. "설문이 필요하겠죠" (미팅) |
| 발송 리스트 확정 (제외 처리) | 코어 플로우 3단계 |
| AI 메일 생성 + 진행 화면 | 코어 플로우 4단계 |
| 메일 전문 검수·인라인 수정 | 코어 플로우 5단계 |
| 발송 승인 팝업 플로우 (책임 고지) | 리스크 관리, 미팅 합의 |
| 대량 발송 인프라 | MVP 필수 (기술 검토 필요) |
| 회신 인박스 + 분류 | "회신만 먹기 좋게" — 핵심 가치 |

## 3. 프로토타입의 역할 재정의

- **지금 배포본(nexport-platform.vercel.app)** = IR·영업용 데모 + 랜딩. **그대로 유지.**
- **PRD 기준 제품** = 디원솔루션 디자인 + 신규 개발. 프로토타입 코드를 계승하지 않음.
- 따라서 이 리포에서 기능을 물리적으로 삭제할 필요는 없음 — 로드맵상 분류(위 표)가 PRD에 반영되면 충분.
- 단, **랜딩/데모에 "매출 보장" 뉘앙스 카피가 남아있는지는 별도 점검 필요** (옵션 B− 정합성).
