# 디원솔루션 회의 녹취 상세 분석 (2026-08-13, 75분)
**성격:** 카톡 요약본(8/11자 정책 리스트)보다 한 단계 깊은 실무 논의 + 실제 Apollo 데이터 라이브 검증
**핵심 결론:** 정책 8개 중 ③(매칭 UX)·④(노출 정책)·⑤(랭킹)의 방향이 회의 중 사실상 전환됨

## 1. 회의에서 확정/합의된 사항

### 1-1. 샘플 데이터 선제공 (개발 착수의 전제조건)
- 디원솔루션: "개발 전에 그 데이터 무조건 먼저 보고 가야 한다" — 데이터 성질을 모르면 세그멘테이션 가능 여부 자체를 판단 불가
- **Jay 액션:** Apollo 샘플 데이터 전달 (합의 완료)
- 추가: LinkedIn 데이터도 구매해 비교 예정. 단, Apollo 자체가 LinkedIn 베이스라 "LinkedIn이 틀리면 Apollo도 틀린다"는 구조적 한계 인지

### 1-2. 개발 난이도 배분: 40 / 60
- 메일 발송 + AI 초안 + 보고서 생성 = 전체의 **40%** ("전혀 어렵지 않다")
- 데이터 정제 + 상단 랭킹 로직 + 관리자 페이지 = **60%**
- 함의: 개발비 협상과 일정의 무게중심은 눈에 보이는 기능이 아니라 백단 데이터 로직

### 1-3. 트래킹 기술 상세 (⑥ 구체화)
- 방식 확정: 자사 도메인에 호스팅한 이미지 + 식별 토큰을 HTML 본문에 삽입 (첨부 아님). 수신자가 열면 로드 시점에 기록 — 수신자 액션 불필요
- 한계 3가지 (개발자 명시):
  1. 스팸 필터가 리소스를 강제 로드하는 경우 → 위양성. **실제 테스트 필수**
  2. 읽음확인(수신확인)은 메일 도메인별로 동작이 달라 신뢰 불가 (네이버 등)
  3. 회신 트래킹은 별개 문제
- 부가 기능 가능: 카탈로그 열람 트래킹, 반복 발송에도 기록이 안 잡히면 "차단 추정" 판별
- 발송은 외부 메일앱 연동이 아니라 **플랫폼 내부에서** (외부로 나가면 트래킹 불가)

### 1-4. 매칭 락(lock) 해제 정책 (신규 이슈)
- 문제 제기(백엔드 개발자): 바이어 1명 = 유저 1명 독점 매칭인데, 불발 시 영구 락 걸림
- 합의 방향: **기간 기반 해제** — 예시로 "2주 무반응 → 매칭 해제, 바이어는 새 매칭 풀로 복귀"
- **기간 수치는 Jay가 영업 경험 기반으로 확정해야 함** (디원솔루션이 명시적으로 요청)
- 죽은 데이터 규칙 예시(Bunkershot 측): "5번 매칭됐는데 5번 다 무반응 → dead data로 폐기"
- 미해결: 거래가 메일 밖(전화, 타 채널)으로 넘어간 경우 락 유지 판별 → 1-5의 영업보고서가 해답

### 1-5. 내부 영업 보고서의 진짜 목적 (⑦ 재정의)
- 표면 기능: 주니어 실무자가 상사에게 월간 보고 → "넥스포트 계속 결제할 명분" = 리텐션 장치
- **숨은 핵심 목적: 오프-플랫폼 활동 트래킹.** 대화가 회사 메일/타 채널로 넘어가면 넥스포트는 추적 불가 → 보고서에 유저가 직접 체크하는 필드("별도 메일 주고받음", "카탈로그 발송함")를 넣어 그 데이터를 회수
- 설문조사·푸시 알림 방식은 명시적으로 기각 ("나 같아도 안 한다") — 유저가 자발적으로 쓰게 되는 편의 기능에 트래킹을 심는 구조

## 2. 방향이 전환된 사항 (v0.1 문서 수정 필요)

### 2-1. ③ 매칭 UX: 카테고리 박스 → **서술형(주관식) 우선** ★
- 라이브 데모에서 Apollo 키워드 품질 문제가 실물로 확인됨:
  - 비닐 제조사에 무관한 키워드 다수, 디자인·마케팅 회사에 '쇼핑' 키워드, CNC 금속가공 업체가 'Internet Service Provider', 'Government'로 라벨링
  - 원인: LinkedIn 기반 키워드 = 회사 사업영역 + **개인 관심사**가 뒤섞임
- 개발자 판단: "저걸 카테고리로 다 나누는 건 불가능하고 짜증나는 일. 어차피 AI로 판단할 거면 **입력도 주관식으로** 받는 게 맞다"
- 토큰 비용: "그렇게 많이 안 든다" — 카톡 요약본의 '비용 상승' 우려는 사실상 해소
- 세분류 주의: 소분류로 갈수록 매칭 확률이 오히려 떨어짐. 중분류 수준 + AI 유사도가 현실적
- UX 안전장치: 대분류 카테고리는 **최후의 보루**로 유지 + "직접 입력" 버튼 병행
- **전환 아이디어 (개발자 제안):** 가입 시점에 "네가 입력한 소개 기반으로 유사 바이어 5개"를 한 줄 요약으로 보여주고 새로고침 가능하게 → 가입 단계에서 가치 증명

### 2-2. ④ 노출 정책: 리스트 브라우징 → **자동 추천 푸시 모델** ★
- Bunkershot 측 강경 입장: "리스트를 쭉 보여주면 안 된다" — 최고 요금제 1회 결제 후 전체 스크래핑 → 재판매 리스크
- 합의 구조:
  - 요금제별 **월 N건 자동 선별 추천** (예: 최하위 5건/월, 상위는 더 많이)
  - 프리미엄 = 수량이 아니라 **품질 차등**: 골드 등급(상단 검증) 바이어 위주 추천
  - 이메일 등 연락처 비노출, 대신 **AI 한 줄 요약** ("이 기업은 랩·비닐 제조사입니다")으로 가시성 확보
- v0.1 고객여정 E단계(검색→열람→크레딧 소모)는 이 모델로 전면 수정 필요

### 2-3. ⑤ 랭킹: Free tier = 데이터 검증 엔진 ★
- MVP의 진짜 목적 (Bunkershot 측 정리): "유효 데이터와 죽은 데이터를 나누는 것"
- 구조: 초기 무료 유저가 대량 발송("융단 폭격") → 반응 오는 바이어 = 산 데이터, 무반응 = 죽은 데이터 → 라벨링 축적 → 본 버전에서 검증된 상단 데이터를 유료로 판매
- **"프리 유저가 우리의 데이터 선별 도구"** — 무료 정책은 비용이 아니라 데이터 자산 구축 투자
- 파생 요구사항: 데이터가 걸러질수록 신규 데이터가 계속 유입돼야 함 → **지속 구매/수집 데이터 파이프라인** 필요 (일회성 구매 불가)
- 개발자의 MVP 대안 제시: "5개 보내고 2주 내 미열람 시 2차 발송, 그 5개에 대한 리포트 제공" — 읽힘을 보장하는 선별력 자체를 상품화
